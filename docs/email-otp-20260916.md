# 邮箱验证码注册与登录

> 历史方案：已被同日后续的邮箱密码登录替代。当前实现见 [password-auth-20260916.md](password-auth-20260916.md)。

/login/ 与 /register/ 统一使用邮箱验证码。首次发送允许创建用户，验证成功后才建立登录会话；昵称在个人中心设置。已有用户保留资料，管理员仍仅由服务端 ADMIN_EMAILS 决定。

接口：POST /api/auth/otp/send/ 接收 email，调用 Supabase /auth/v1/otp（create_user: true）；POST /api/auth/otp/verify/ 接收 email、code，调用 /auth/v1/verify（type: email），随后通过 /user 验证身份并设置 HttpOnly、SameSite=Lax 的会话 Cookie。客户端不接收访问令牌。旧密码登录/注册接口返回 410，提示刷新页面。

Supabase 邮件模板必须同步配置：Confirm sign up 和 Magic link or OTP 使用 {{ .Token }}，不再要求点击 {{ .ConfirmationURL }}。现有 SMTP 保持不变。验证码位数由服务端配置，界面兼容 6–8 位；重发间隔 60 秒，实际限频、有效期和一次性验证由 Supabase 控制。请保留邮件验证和服务端限流。会话仍最多一小时，未新增自动续期。

验证：node --test tests/email-otp.test.mjs tests/user-account.test.mjs tests/login-origin.test.mjs tests/supabase-api.test.mjs；pnpm exec tsc --noEmit；pnpm build。覆盖错误/过期验证码、账户与邮箱不匹配、跨站请求、发信限流、令牌不回传、管理员边界和安全 Cookie。

## 线上切换记录

截至本地修改完成时，项目 OTP 长度为 8 位、有效期 3600 秒。界面允许 6–8 位以兼容现有配置，实际校验以 Supabase 为准。两个邮件模板已在 Supabase 保存为下述内容。上线时须确认 Vercel 部署成功，并通过正式域名完成一次真实验证码登录；本地构建不代表上线验收。
